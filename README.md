## Дипломный проект. Задание 2: тестирование API

### Структура проекта

- `tests` - файлы с тестами;
- `conftest` - фикстуры для создания уникальных пользователей и заказов с удалением после;
- `helpers` — функции, генерирующие рандомные тестовые данные (Faker);
- `data` - предопределенные тестовые данные;
- `urls` - адреса сервиса и его эндпоинтов;
- `allure_results` - JSON-файлы с результатами выполнения тестов;
- `requirements.txt` - все внешние зависимости исполняемых тестов;
- `README` - мануал

### Сценарии

- `test_registration` - проверка позитивных сценариев создания пользователя, отправка запросов с уже зарегистрированным email и незаполненными обязательными полями;
- `test_authentication` - аутентификация существующего в базе пользователя с валидным паролем, невалидным паролем, а также реакцию системы на запрос аутентификации с незарегистрированным паролем;
- `test_create_order` - создание заказа с верным, неверным и неуказанным хэшем ингредиентов, а также с аутентификацией и без аутентификации пользователя;

### Запуск автотестов

> `$ pip install -r requirements.txt` - установка зависимостей

> `pytest -v` - запуск тестов с очетом в терминале

> `allure serve allure_results` - отчет о тестировании в формате web страницы
> rm -rf allure-results/ && pytest --alluredir=./allure-results && allure serve ./allure-results
> `` - очистка папки с отчетом, запуск теста и формирование allure отчета с открытием web страницы
